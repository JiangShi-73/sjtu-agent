# PathFinder SJTU 首版需求

## 首版要解决的问题

面向正在准备推免夏令营或校招的交大学生。用户选定一个机会后，能看清自己满足哪些要求、还要补什么，以及接下来几天该做哪些准备。

首个交付是手机和电脑都能用的响应式 Web 原型。业务数据和规则通过统一的数据契约访问，方便后续 Web 和 App 接入同一服务。首版暂按夏令营和校招两类机会设计，首条演示用夏令营走通。

**主流程**　填写个人背景 → 选择机会并查看原文 → 逐项核验 → 编辑并确认申请计划 → 下载 `.ics`。

## 功能与验收

| 功能 | 首版交付 | 验收条件 |
| --- | --- | --- |
| 个人背景 | 手填专业、年级、专业排名百分比、CET-6 成绩和经历标签。提供示例一键填充和清空入口 | 选学术或求职机会都能复用同一份画像。排名限 0–100，数值输入须合法。空值表示未知。经历标签未填写与明确无相关经历可区分 |
| 机会浏览 | 读取预置样例，按机会类别筛选，进入详情看来源、要求、材料和截止日 | 样例带醒目标识。真实条目展示来源链接和关键原文。过期机会仍可查看，并标明已截止 |
| 条件核验 | 硬性条件按规则逐条判断，软性偏好显示画像中相关经历及展示建议 | 每条硬性条件显示要求、用户填写值、结论、原文依据。阈值包含等号时按原文处理。缺字段或无法解释的规则标为“待核实” |
| 申请计划 | 根据机会材料生成任务。用户确认准备天数，可调整实际任务日期 | 暂无截止日时，可手动确认一个规划用目标日，并标为用户设定。任务日期超出目标日时给出提示，晚于目标日的任务需修正后才能导出 |
| 日历导出 | 将准备任务及申请目标日生成 `.ics` | 用户确认计划后可以下载。导入日历后任务标题和日期与计划一致。已截止机会禁用生成和导出 |

## 业务规则

- **硬性条件**使用“已满足 / 待核实 / 不满足”。支持专业所属范围、数值上限和下限。排名百分比越小越靠前。不同考试的成绩不互换，CET-6 缺失时按未知处理。
- **软性偏好**使用“已有相关经历 / 可补充 / 待核实”。标签为空数组表示用户确认没有相关经历。已填写的标签未命中时显示“可补充”，标签未填写时显示“待核实”。软性结果不影响硬性条件汇总。
- **核验结论**按“不满足 → 待核实 → 已满足”取最高优先级。无可核验的硬性条件时显示“待核实”。存在差距时用户仍可生成准备计划，页面保留对应提示。
- **日期**用 `YYYY-MM-DD` 表示，机会状态和日历日期按中国标准时间理解。只有日期的通知按日展示，页面不推断具体截止时刻。日期早于今天时标记已截止。准备天数按自然日倒推，`任务日期 = 规划目标日 − 用户确认的准备天数`。系统单独将目标日作为提交日期展示和导出，每条材料任务也各导出一次。
- **编辑与导出**。早于今天的任务提示用户调整，用户可确认保留历史任务。修改任务或目标日后需要重新确认才能导出。改目标日期时保留手动调整过的任务日期，按新目标日重算未手动调整的任务，并重新提示日期冲突。
- **首版数据留存**。浏览器本地保存画像与各机会计划，提供清空入口。清空画像后重新打开核验页时用当前空画像计算。机会样例与个人数据分开保存。首版画像不收集姓名、学号和联系方式。

## 两端共用的数据契约

| 对象 | 关键字段和约定 |
| --- | --- |
| `Profile` | `majorCategory`、`studyYear`、`rankPercent`、`cet6Score`、`experienceTags`。未知用 `null`，经历已填但为空用 `[]` |
| `Opportunity` | `id`、`type`、`title`、`publisher`、`publishedDate`、`deadlineDate`、`source`、`requirements`、`materials`。日期不明用 `null`。`source` 保存类型、链接和原文。演示样例的 `source.kind` 为 `demo`，url 为 `null` |
| `Requirement` | `id`、`kind`、`label`、`field`、`operator`、`value`、`evidence`。首批操作为 `lte`、`gte`、`in`、`includes` 和 `manual`。`manual` 始终待核实 |
| `Assessment` | `opportunityId`、`summary`、`items[]`。每项含 `requirementId`、用户值、状态、解释，由当前画像实时计算 |
| `Plan` | `opportunityId`、`targetDate`、`targetDateSource`、`tasks[]`、`confirmed`。每项含稳定 ID、名称、准备天数、截止日期和是否手动调整 |

页面通过统一入口完成机会查询、核验、计划和日历导出。首版可用本地样例、规则和本地存储实现。接入后端时，Web 和 App 复用同一套数据结构与规则模块，或由后端在同一处执行规则。

材料上传、全量信息采集、水源社区、账户与跨设备同步、日程冲突和通知推送进入后续版本。第一条流程由规则完成。AI 可在后续版本辅助提取信息和解释建议。
