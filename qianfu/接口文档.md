# 信鸽 SJTU 接口文档

全部接口挂在 `http://127.0.0.1:8722/api/v1`，共 **68 个**。

在线调试：<http://127.0.0.1:8722/docs>

## 三层结构

~~~
QQ 用户
  ↓
AstrBot + xinge 插件   →  /bot/*      19 个，机器人的全部能力
  ↓
信鸽前端 / Agent        →  /agent/*   2 个，模型调接口
  ↓
抓取内核 xinge         （不对外）
~~~

## 通用约定

| 约定 | 说明 |
|---|---|
| 返回格式 | JSON，UTF-8 |
| 时间格式 | `YYYY-MM-DD HH:MM` |
| `format=text` | 列表接口支持，直接返回排好版的文本，机器人转发即可 |
| `limit` | 条数上限，默认值见各接口说明 |
| 错误 | `{"detail": "..."}`，HTTP 4xx/5xx |

## Agent 对话怎么工作

和 Dela 一样的思路：**工具注册表 + function calling 循环**。

~~~
用户提问
  → 模型看到 11 个工具的定义
  → 模型决定调哪个（可多轮）
  → 信鸽本地执行，结果回灌给模型
  → 模型组织最终回答
~~~

工具不重复实现业务，全部打到信鸽自己的 HTTP 接口上——接口一改，工具跟着变，
不会出现两套逻辑。

`GET /agent/tools` 能看到当前暴露的 11 个工具。

## 接口管理

左侧「接口」按钮打开管理面板，两组开关：

| 分组 | 数量 | 作用 |
|---|---|---|
| 问助手的工具 | 11 | 关掉的工具模型看不见，也调不到 |
| 机器人的接口 | 16 | 关掉的接口直接返回 403 |

存储：`~/.xinge/config.json` 的 `api_tools` / `api_bot`。

~~~json
{
  "api_tools": {"list_mail": false},
  "api_bot": {"/api/v1/bot/mail": false}
}
~~~

接口：

~~~http
GET   /api/v1/api/manage            两组清单和开关状态
PATCH /api/v1/api/manage            {kind, key, enabled}
~~~

`kind` 是 `agent`（工具）或 `bot`（接口）。


## jAccount 单点登录

一次登录，所有走 jAccount 的站自动进。

信鸽只需要**一次** jAccount 登录（Canvas 扫码那次），之后：

~~~
带着 jaccount.sjtu.edu.cn 的 cookie 请求目标站
  → 目标站 302 到 jaccount.sjtu.edu.cn/jaccount/url?sid=<站>
  → JAAuthCookie 有效，jAccount 直接放行
  → 302 回目标站，带 ticket
  → 目标站回写自己的会话 cookie
~~~

不用再输密码，也不用弹浏览器。

### 已支持的站

| 站 | 方式 | 状态 |
|---|---|---|
| 水源社区 | SSO | 已验证 |
| 好大学在线 | SSO | 已验证 |
| 体育 | SSO | 已验证 |
| Canvas | 令牌 | 用 API token |
| 校园活动 | 令牌 | 登录时自动换 JWT |

### 加一个新站

`xinge/jaccount.py` 的 `SITES` 里加一行：

~~~python
"library": {
    "name": "图书馆",
    "url": "https://lib.sjtu.edu.cn/",
    "check": ["SESSION", "JSESSIONID"],   # 出现任意一个就算成功
    "method": "sso",
},
~~~

然后调 `POST /api/v1/jaccount/sso/library` 就能进。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/jaccount/status` | jAccount 会话状态 + 各站登录情况 |
| POST | `/api/v1/jaccount/sso/{site}` | 对某个站做一次 SSO |
| POST | `/api/v1/jaccount/sso` | 所有站都试一遍 |

### 两种登录方式

- **sso**：带着 jAccount cookie 走一次重定向就能进，cookie 存在 `~/.xinge/<site>.json`
- **token**：站自己发令牌（OAuth / JWT），SSO 只能证明身份，还得走它自己的接口


## 教务课表

`i.sjtu.edu.cn` 走 jAccount OAuth：`/jaccountlogin` 会 302 到 jaccount，
拿到 code 再换回教务自己的 `JSESSIONID`。

课表接口是正方那套：

~~~http
POST https://i.sjtu.edu.cn/kbcx/xskbcx_cxXsKb.html?gnmkdm=N2151
     xnm=2026  xqm=3  kzlx=ck
~~~

返回的 `kbList` 每条是「一门课 × 一个星期 × 一个节次」。

### 两个坑

**① `dateDigitSeparator` 不是上课日期**

它给的是**本周周一**，所有课都一样。真正日期要自己算：

~~~python
day = 周一 + (星期几 - 1) 天
~~~

**② 节次要换成时间**

`jcs` 是「3-4」「11-13」这种，得映射到具体钟点：

| 节次 | 时间 |
|---|---|
| 1-2 | 08:00-09:40 |
| 3-4 | 10:00-11:40 |
| 5-6 | 14:00-15:40 |
| 7-8 | 16:00-17:40 |
| 9-10 | 18:30-20:10 |
| 11-13 | 20:20-22:55 |

### 接口

| 方法 | 路径 | 说明 |

## 调用示例

**查作业**

~~~bash
curl "http://127.0.0.1:8722/api/v1/bot/canvas?limit=5&format=text"
~~~

**问助手**

~~~bash
curl -X POST http://127.0.0.1:8722/api/v1/agent/chat \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"这周有什么要交的？"}]}'
~~~

返回：

~~~json
{
  "reply": "最近 7 天内要交的有 3 项……",
  "steps": [
    {"tool": "get_deadlines", "args": {"days": 7}, "result": "..."}
  ],
  "usage": {"prompt": 1234, "completion": 456}
}
~~~

`steps` 是工具调用记录，前端用它显示「→ get_deadlines」这种过程提示。

**开关学院订阅**

~~~bash
curl -X PATCH http://127.0.0.1:8722/api/v1/colleges/cs \
  -H "Content-Type: application/json" \
  -d '{"enabled": false}'
~~~
